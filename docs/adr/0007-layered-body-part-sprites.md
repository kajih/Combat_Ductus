# Characters are rigged from layered body-part sprites, not whole-body attack frames

Today each Body Type ships one whole-body PNG per attack (idle/punch/kick), so three Body Types means nine full-body frames, and every new attack means a new full-body frame per Body Type. Instead, a Character is composited at runtime from separate body-part entities — torso (carrying the head and the existing viewer-facing face-photo slot from [0006](0006-face-photos-stay-viewer-facing.md)), arm, and leg — each attached to the torso at a socket offset defined per (Body Type, Facing). This is the same compositing pattern [0006](0006-face-photos-stay-viewer-facing.md) already uses for the face photo, extended to the rest of the body. An attack no longer swaps the whole-body texture; it swaps or briefly animates just the arm (Punch) or leg (Kick) entity, leaving the torso and head untouched.

Because Facing is fixed for a whole Match ([0002](0002-fixed-facing-no-turning.md)) and Body Type is a closed set of three cosmetic proportions ([0003](0003-body-type-cosmetic-only.md)), the socket data this requires is bounded and known up front — two Facings times three Body Types — not something that grows with the Roster. The payoff is in future Specials: a new Special can reuse the existing torso and legs and introduce only a new arm or leg asset, rather than a full new whole-body frame per Body Type, which is the main reason to make this change now rather than after more attacks are built on the whole-body-frame model.

The cost is one-time rework of the nine committed whole-body PNGs into torso/arm/leg pieces cut to a shared anchor grid per Body Type, plus a per-attack z-order rule (e.g. arm drawn in front of torso on Punch) that whole-body frames never needed since the whole pose was baked into one image.
