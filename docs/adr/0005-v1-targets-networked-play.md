# v1 targets networked (client-server) play, not local multiplayer

We could have shipped local 2-player (shared keyboard, one machine) as a stepping stone and added network play afterward. Instead, v1 is architected around network play from the start: one machine acts as server, the other as client. The server is the single source of truth — it runs the one true simulation of the Match every tick and streams positions/state to the client, which only renders what it's told rather than running any simulation of its own. There is therefore no independent "opinion" on either side to reconcile, and no desync problem to solve: this is a deliberate simplification, judged acceptable because play happens over a local, low-latency LAN (same room), not the internet, so the cost of the client always deferring to the server is imperceptible. The first milestone deliberately accepts an Idle Opponent (a stationary, unclaimed Player 2) rather than building out local same-keyboard multiplayer as an interim step, since local multiplayer would be throwaway work once real network play lands.
